执行顺序：

8. **汇总**：备份路径、打码 diff、一行回滚命令、新密钥前 6 字符与长度

说明：脚本为了一次无资源冲突的 `check` 会短暂停服约 5~10 秒，随后立即以新配置启动；有 flock 单实例锁。

### 5.1 实际执行结果（2026-10-08）

**第一次执行（13:35:51）——误报回滚，正式配置未落盘。**
- 现象：`sing-box check` 通过 → 原子替换成功 → 健康检查报「端口未监听: 7892 9090 9091」→ 自动回滚，服务恢复。
- 排查证据：① systemd 日志显示新实例是 `Stopping → Deactivated successfully`（被脚本主动停），**不是崩溃**——没有 `Main process exited` / `Failed with result`；② 新实例存活 586ms / 538ms、各耗 CPU 538ms，说明它正在正常启动过程中就被判失败；③ 同期测试脚本 T1.3 也报端口缺失，但几秒后 T2/T3 全部连通。
- 根因（**脚本 bug，非配置问题**）：unit 为 `Type=simple`，`systemctl is-active` 在进程 fork 后立即返回 active，而健康检查**零等待**就查端口；sing-box 加载 17 个 rule-set + eBPF 程序需要数秒。
- 修复：端口检查改为**最长 60 秒轮询**（进程若自行退出则立即判失败），真失败时**先打印新实例最后 40 行日志再回滚**。

**第二次执行（13:45:03 生效）——成功。**
- 流程：`sing-box check` 通过 → 原子替换（16641 B, mode 600）→ 启动 → 全套健康检查通过 → 未触发回滚。
- 独立复核（emo 权限，13:53 实测）：systemd `active`，MainPID 168960；`Wants=network-online.target` 已进事务；7892/9090/9091/9096 全部 LISTEN；`outbounds` 由 22 → **21**（`block` 出站已移除）；CORS 对 `https://evil.example` **不再返回** `Access-Control-Allow-Origin`，对 `http://127.0.0.1:9096` / `http://localhost:9096` 分别回显该源；无密钥访问 9090 → 401；经 7892 代理 gstatic → 204（0.33s）；出口 IP <proxy-exit-ip>；新配置启动后 journalctl 无新增 ERROR（最近一条 ERROR 为 13:34:32，属切换前的旧配置）。

### 6.2 关于「Akamai 回声是国内 IP」的说明（重要，避免误判为泄漏）
`whoami.akamai.net` 的回声是 <home-ip>（AS4134 中国电信四川），但这是**直连解析分流**造成的：该名字命中 must-direct / dns-direct 规则，由国内递归解析器解析，Akamai 权威侧看到的是国内递归地址。CDN/国内域名走直连解析是常见且正确的设计，**不是 DNS 泄漏**。真正的泄漏判据是 T5.1 的 Google ECS 回声是否落在国内网段——实测落在 Cloudflare，判定通过。

## 七、第 6 步 · 回滚步骤与维护建议

### 7.1 回滚（三层，任选）
1. **配置回滚（最常用）**：
   ```
   sudo install -m 600 -o root -g root /etc/sing-box/config.json.bak.<时间戳> /etc/sing-box/config.json
   sudo systemctl restart sing-box
   systemctl is-active sing-box && ss -ltn | grep -E '7892|9090|9091'
   ```
2. **drop-in 回滚**（只撤开机等待网络）：`sudo rm /etc/systemd/system/sing-box.service.d/20-network-online.conf && sudo systemctl daemon-reload`
3. **备份权限回滚**（一般不需要）：`sudo chmod 755 /etc/sing-box/backups; sudo find /etc/sing-box -maxdepth 1 -name 'config.json.bak.*' -exec chmod 644 {} +`

### 7.2 维护建议
1. **每季度**跑一次本审计的两个脚本（先 --dry-run 看 diff）；sing-box 有新版时先在 `--dry-run` 下核对 deprecated 列表。
2. **统一脚本来源**：只从 /home/emo/pkgbuild-source 运行同步脚本，删除或同步 Singborg 里的旧副本，消除 S1 漂移。
3. **备份保留**：保留「最新 10 份 + 7 天内不归档」，归档文件另存到加密盘更稳妥；备份里含明文凭据，务必保持 600。
4. **密钥轮换**：本次轮换后，建议每 6 个月轮换一次；轮换只需改配置并重启，面板自动跟上。
5. **待你确认的新项**：`chmod 600 /var/lib/sing-box/cache.db`（当前 644，本地可读 DNS 查询历史）。这不在已授权的 14 项内，你点头我再加进脚本。
6. **节点口令复用**（第 7 项）属服务商侧，建议在服务商面板逐节点改独立口令。
7. **监控**：`journalctl -u sing-box -p warning --since today` 每周扫一遍；`missing default interface` 应在 drop-in 生效后不再出现。
8. **不要**把 `experimental.clash_api.secret` 写回任何会进 git 的文件；generate-sanitized-config.py 修好后再用它生成公开快照。
