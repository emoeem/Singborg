## 1. DNS 泄露（实测证据）

```
① 53 端口劫持：dig @8.8.8.8 / @192.168.31.1 / @223.5.5.5 / @1.1.1.1 doubleclick.net
   → 四个全部返回空（说明查询都进了 sing-box 的 DNS 规则，而不是真的发到那些解析器）

② 出口回显：dig TXT o-o.myaddr.l.google.com
   → 系统解析器与 @1.1.1.1 都返回 172.64.212.11（Cloudflare 的解析出口）
   → 海外域名由 Cloudflare DoH 经代理解析，ISP 看不到

③ 明文 DNS：ss -un / -tn 里没有任何指向外部 :53 的套接字
   → 没有 UDP/53 明文外发（sing-box 走 DoH over 443）
   现存 53 监听者只有本机服务：127.0.0.53/54（systemd-resolved）、192.168.122.1（libvirt）

④ 国内解析：ss 显示到 223.5.5.5:443 的 DoH 连接
   → 国内域名走阿里 DoH（不是明文 UDP，比之前那版更强）

⑤ resolvectl：tun0 = 172.19.0.2 / fdfe:dcba:9876::2，DNS Domain ~.
   → 系统解析器 100% 指向隧道
   （**追注 2026-10-02 23:01：这是 TUN 模式下的状态，现已不适用**——当前 eBPF 模式没有 tun0，
   `resolvectl` 里 wlan0 用 `192.168.31.1` 与宿主路由器的 ULA 网关（`fd00:6868:…::1`），解析器不再指向隧道；
   劫持改由 eBPF 在 53 端口完成，实测 `dig @8.8.8.8 doubleclick.net`、`dig @223.5.5.5 doubleclick.net` 都立刻返回 NXDOMAIN，拦截仍有效。）
```

**唯一残留面**：`dns.servers` 里那个 `dns-local`（`type: local`）现在没人引用；一旦将来被误引用，就会绕过 DoH 走系统解析器 → 建议直接删掉。
（**追注 2026-10-02 23:01：已删除**——当前 `dns.servers` 共 7 条，无 `dns-local`。）

**一个天然限制（你已规避）**：`hijack-dns` 只覆盖 53 端口/`dns` 协议，浏览器自作主张的 **DoH（443）不经过 sing-box 的 DNS 规则**。
好在你的广告拦截**同时写在 `route.rules` 里**（连接层按 sniff 出的域名 reject），所以即使用户开浏览器 DoH，
广告连接照样被 RST —— 这个"双写"设计是对的，别只留 DNS 那一条。

### 10.2 ⚠️ 测量方法更正（重要）

本文档前面所有"DNS 拦截 = ✅"的判定，**用的是"`dig` 无输出"**，而我把 `dig` 的 **stderr 丢掉了** ——
于是"**REFUSED**"和"**超时**"看起来一模一样。带完整输出复测后真相是：

| 查询路径 | 实际结果 |
|---|---|
| 直连任意解析器（`dig @8.8.8.8 / @223.5.5.5 / @192.168.31.1 doubleclick.net`） | **`status: REFUSED`**（立刻返回，是合法 DNS 响应） |
| 经 `systemd-resolved`（`dig doubleclick.net`） | `communications error to 127.0.0.53#53: timed out`；`resolvectl` 自己说 `server or network returned error: REFUSED` |

即：**sing-box 的 DNS `reject` 语义是 REFUSED**，而 **systemd-resolved 不会把 REFUSED 转告客户端**
（它当作"上游故障"去重试其他上游，最终放弃），于是走系统解析器的应用每个广告域名要**等约 5 秒**才失败。
这不影响"拦截有效"的结论（广告域名确实拿不到解析），但**影响体验**，且 TUN 模式同样存在（只是以前没测出来）。

**修法**：DNS 广告规则由 `reject`(REFUSED) 改为 `predefined` + `rcode: NXDOMAIN` ——
NXDOMAIN 是正常应答，resolved 会如实转告，应用立刻失败并做负缓存。该 fork 已实测支持该写法：
`apply-audit-fixes.sh --nxdomain-ads`（干跑 `check` 通过）。

## 11. eBPF 数据面实测（**2026-10-02 13:0x 重要更正**）

> ⚠️ 本节原标题写的是「本机只能用 local `cgroup`（tc / shared 均不可用）」—— **那是错的**。
> 当时只实测了 `local tc`（失败），然后**推断**「shared 也是 TC 路径所以不可用」，
> 而且 shared 从未真跑过（脚本卡在「找不到 podman 网桥」就退出了）。
> 官方文档写明：四条数据面**互相独立**，一条不可用不能推断另一条。
> 以 **root** 权限重新逐条探测后的真实结果：

| 数据面 | 探测结果（`sudo sing-box tools ebpf status … --json`） |
| --- | --- |
| local `cgroup` | `preflight_passed`（PASS 37 / FAIL 0 / UNKNOWN 0） |
| **local `tc`** | ❌ 实测启动失败：`register TC eBPF TCP listener: operation not supported` |
| **shared `packet_rewrite`** | ✅ **`preflight_passed`（PASS 33 / FAIL 0 / UNKNOWN 0）** |
| **shared `socket_assign`** | ✅ **`preflight_passed`（PASS 31 / FAIL 0 / UNKNOWN 0）** |

**更正后的结论**：本机只是 **local `tc`** 这一条不可用，**两条 shared 都可用**
→ **eBPF 模式下容器/虚拟机可以被接管**（这才是「接管本机与共享网络流量」的完整形态），
不必为了容器/VM 覆盖切回 TUN。探测必须用**与服务相同的权限**（普通用户跑只会得到一堆 `unknown`）。

## 12. 决策：切回 TUN 模式（2026-10-02 11:1x）

> **追注（2026-10-02 23:01 复核：本节的决策与理由都已被推翻，结论不再成立）**
> - 本节的**前提是错的**：当时以为"本机内核不支持 TC 路径"，实际只有 **local 的 `tc` 模式**不可用，
>   **两条 `shared` 数据面实测都可用**（§11，`shared=packet_rewrite` 以 TCX 挂在 `virbr0` 上）；
> - "pasta 不创建宿主 socket"这个机制解释也是**错的**（`ss -tnp` 可见 `passt.avx2` 的 ESTAB 宿主 socket，真正卡点未确证，见 §11.0 追注与 `docs/09` §6）；
> - 因此**当天夜间又切回了 eBPF**：当前 `inbounds[0].type="ebpf"`，`local.data_plane=cgroup` + `shared.data_plane=packet_rewrite`（`interface:["virbr0"]`）。
>   所以下表把 eBPF 写成"只有 local `cgroup` 一个数据面"已不符合现状（当前是 `cgroup` + `shared` 两个）；`scripts/switch-to-tun.sh` 保留作回退手段。

§11 一度被读成"本机内核不支持 TC 路径"，据此推断 eBPF 的 local `cgroup` 数据面**覆盖不到 rootless 容器**
（当时以为是"pasta 不创建宿主 socket"）。**这两个前提现已被推翻**（见上追注），
而 TUN 靠 `auto_route` 覆盖转发流量，容器/虚拟机天然被代理。
权衡"eBPF 的新特性"（分应用 UID 策略）与"容器+VM 的完整覆盖"后，当时选择**回到 TUN**：

| 能力 | TUN | eBPF (cgroup) |
|---|---|---|
| 本机流量接管 | ✅ | ✅ |
| **容器（rootless pasta）** | ✅ auto_route 覆盖（**本次未复测**） | ❌ 看不到（除非 `--network=host`；2026-10-02 晚复测仍是境外失败、国内正常） |
| **虚拟机 / 共享网络** | ✅ | ✅ **实测通过**（用 `shared`=`packet_rewrite`，不是 local 的 tc 模式；见 `docs/09` §6） |
| 分应用 UID 策略（面板） | ❌ | ✅ |
| 内核依赖 | 需 TUN 设备 | 需 BPF/cgroup（本机满足） |
